    Bienvenido a KRAT OS
    Simulador educativo de sistema embebido
    Que es KRAT OS
    KRAT OS es un simulador interactivo diseñado para reproducir el comportamiento interno de un sistema embebido. A través de sus módulos, el usuario puede experimentar de forma práctica con conceptos fundamentales de los sistemas de cómputo de bajo nivel: gestión de memoria volátil, sincronización temporal, interacción mediante comandos y comprensión de la arquitectura general de un sistema operativo embebido.
    El nombre KRAT OS proviene de la combinación de conceptos de control y sistema, haciendo referencia al dominio sobre los recursos del hardware simulado.
    Objetivo del Simulador
    El objetivo principal de KRAT OS es proporcionar un entorno educativo donde el estudiante pueda:
    • Comprender el concepto de memoria volátil (RAM) y su comportamiento temporal
    • Experimentar con operaciones de sistema de archivos en un entorno simulado
    • Entender la función del reloj del sistema en un entorno embebido
    • Aprender a interactuar con un sistema a través de una interfaz de línea de comandos
    • Visualizar la interacción entre los diferentes componentes de un sistema

    Todos los datos creados en KRAT OS son temporales. Al cerrar la aplicación, la memoria se libera completamente, tal como ocurre en un sistema real con memoria RAM sin respaldo no volátil.

    Disco en RAM
    Sistema de archivos sobre memoria volátil
    Que es un Disco RAM
    Un disco RAM (también llamado RAM disk o ramdisk) es una porción de la memoria RAM del sistema que se utiliza como si fuera un dispositivo de almacenamiento. A diferencia de un disco duro o una unidad SSD, los datos en un disco RAM no persisten cuando el sistema se apaga o reinicia.
    En sistemas embebidos, esta técnica es ampliamente utilizada cuando se requiere almacenamiento temporal extremadamente rápido durante la ejecución del sistema.
    Como Funciona
    El disco RAM en KRAT OS asigna un bloque fijo de 8 megabytes de la memoria del navegador. Cada archivo creado consume una porción de ese espacio. El sistema lleva un registro preciso de:
    • Nombre del archivo y su identificador único
    • Contenido del archivo como cadena de texto codificada
    • Tamaño calculado en bytes a partir del contenido
    • Marca de tiempo de creación y de última modificación
    // Estructura interna de un archivo { id: "uuid", name: "archivo.txt", content: "Contenido del archivo...", size: 256, // bytes createdAt: Date, // timestamp de creación modifiedAt: Date // timestamp de modificación }
    Ventajas del Disco RAM
    • Velocidad de acceso extremadamente alta — igual a la velocidad de la RAM
    • Sin latencia de escritura ni cabezales que posicionar
    • Ideal para archivos temporales de alta frecuencia de acceso
    • Reduce el desgaste de dispositivos de almacenamiento físicos
    • Predecible y sin fragmentación en su funcionamiento
    Desventajas del Disco RAM
    • Volatilidad total: todos los datos se pierden al apagar el sistema
    • Capacidad limitada al tamaño de la RAM disponible
    • No apto para almacenamiento persistente entre sesiones
    • Mayor costo por GB comparado con almacenamiento físico
    Aplicaciones Reales

    Sistemas Linux

    tmpfs y ramfs son implementaciones de disco RAM nativas en Linux, usadas para /tmp y /run.

    Sistemas Embebidos

    Routers, PLCs e industria automotriz usan RAM disks para logs y buffers temporales de alta velocidad.

    Servidores Web

    Cachés de bases de datos y archivos de sesión se almacenan en RAM para reducir latencia de I/O.

    IoT y Sensores

    Dispositivos de bajo consumo almacenan lecturas en RAM antes de transmitirlas al servidor central.

    Reloj del Sistema
    Sincronización temporal en sistemas embebidos
    Que es el Reloj del Sistema
    El reloj del sistema es uno de los componentes más críticos en cualquier sistema de cómputo. Se trata de un contador que avanza de forma continua y que proporciona una referencia temporal a todos los demás componentes del sistema. En hardware, este contador suele estar respaldado por un oscilador de cristal de cuarzo que garantiza su precisión.
    Los sistemas operativos utilizan este reloj para múltiples propósitos: registro de eventos, planificación de procesos, gestión de timeouts, y sincronización con servidores de tiempo externos (NTP).
    Para Que Sirve
    • Marcar la hora y fecha de creación y modificación de archivos
    • Planificar la ejecución de tareas en momentos específicos
    • Medir el tiempo de ejecución de procesos y funciones
    • Sincronizar la comunicación entre diferentes componentes del sistema
    • Registrar eventos con marcas de tiempo precisas para auditoría
    • Implementar watchdogs y mecanismos de timeout
    Relacion con los Sistemas Embebidos
    En sistemas embebidos, la gestión del tiempo tiene particularidades importantes. Muchos microcontroladores incluyen un módulo llamado RTC (Real-Time Clock) que puede mantener la hora incluso cuando el sistema principal está apagado, gracias a una batería de respaldo.

    Un sistema embebido sin reloj preciso puede comprometer la integridad de logs, la planificación de tareas y la sincronización de comunicaciones. Por eso el RTC es considerado un componente esencial en cualquier diseño embebido serio.

    El uptime del sistema (tiempo de actividad continua) es un indicador clave de la estabilidad del sistema. En KRAT OS, este valor se calcula desde el momento en que la aplicación es iniciada, simulando el comportamiento de un sistema embebido real.
    Componentes del Módulo
    • Reloj de tiempo real con actualización por segundo
    • Cronómetro con capacidad de registrar vueltas parciales
    • Temporizador configurable en horas, minutos y segundos
    • Panel de uptime desglosado en dias, horas, minutos y segundos
    • Registro de eventos con marca de tiempo
    Terminal
    Interfaz de línea de comandos del sistema
    Que es una Terminal
    Una terminal (también llamada consola, shell o CLI — Command Line Interface) es una interfaz de texto que permite al usuario interactuar directamente con el sistema operativo mediante la escritura de comandos. Es la forma más directa de comunicarse con el núcleo del sistema, sin capas gráficas intermedias.
    En sistemas embebidos, la terminal es frecuentemente la única interfaz disponible para diagnóstico, configuración y mantenimiento del sistema, ya que muchos dispositivos embebidos no cuentan con pantalla gráfica o teclado físico.
    Como Interactua con el Sistema
    Cada comando ingresado pasa por un proceso de interpretación:
    Entrada
    →
    Parser
    →
    Dispatcher
    →
    Módulo
    →
    Respuesta
    El parser separa el comando de sus argumentos. El dispatcher identifica qué módulo debe ejecutarlo. El módulo procesa la acción y devuelve la respuesta que se muestra en pantalla.
    Comandos Disponibles
    help — Muestra todos los comandos disponibles time — Muestra la hora actual del sistema date — Muestra la fecha completa actual uptime — Muestra el tiempo de actividad del sistema clear — Limpia la pantalla de la terminal ls — Lista todos los archivos del disco RAM create archivo.txt — Crea un nuevo archivo vacío read archivo.txt — Muestra el contenido de un archivo delete archivo.txt — Elimina un archivo del disco RAM rename arc1.txt arc2.txt — Renombra un archivo existente memory — Muestra estadísticas de uso de memoria exit — Regresa al panel principal
    Historial de Comandos
    La terminal de KRAT OS implementa un historial de comandos navegable mediante las teclas de flecha hacia arriba y hacia abajo, de la misma forma que terminales reales como Bash o Zsh. Esto permite recuperar y reutilizar comandos anteriores sin necesidad de volver a escribirlos.
    • Flecha arriba: comando anterior en el historial
    • Flecha abajo: comando siguiente en el historial
    • Enter: ejecutar el comando actual
    • Tab: (simulado) completado de nombre de archivo
    Funcionamiento General
    Arquitectura e interacción de módulos en KRAT OS
    Como Interactuan los Modulos
    KRAT OS está diseñado bajo el principio de módulos interdependientes que comparten un estado centralizado. Cada módulo tiene acceso a los recursos del sistema pero mantiene su propia lógica de presentación. El estado global incluye:
    • El mapa de archivos del disco RAM (compartido por el módulo de archivos y la terminal)
    • Los contadores de tiempo (compartidos por el reloj, dashboard y registro de eventos)
    • El registro de actividad (accesible desde cualquier módulo)
    • Las estadísticas de memoria (calculadas dinámicamente y reflejadas en el dashboard)
    Flujo de Funcionamiento
    Cuando el usuario interactúa con KRAT OS, el flujo general de procesamiento sigue este camino:
    Usuario
    →
    Interfaz GUI / Terminal
    →
    Controlador de Módulo
    →
    Estado RAM
    →
    Actualización UI
    Este patrón garantiza que el estado del sistema sea siempre consistente, independientemente de si el usuario opera desde la interfaz gráfica o desde la terminal de comandos.

    Sincronizacion en Tiempo Real
    KRAT OS utiliza un bucle de actualización principal que se ejecuta cada segundo para mantener todos los indicadores sincronizados. Este mecanismo es análogo al tick del sistema operativo en sistemas reales, donde el temporizador del hardware genera una interrupción periódica que el kernel utiliza para actualizar su estado interno.

    En un sistema embebido real, este mecanismo se implementa mediante interrupciones de hardware generadas por el RTC o un timer dedicado. KRAT OS lo simula usando el API de temporización del navegador web.

    Aplicaciones Reales de estos Componentes

    Industria Automotriz

    Los sistemas ECU de los vehículos modernos utilizan RAM disks para almacenar datos de diagnóstico temporales y logs de sensores.

    Telecomunicaciones

    Routers y switches utilizan discos RAM para tablas de enrutamiento y cachés de resolución de nombres que requieren acceso ultrarrápido.

    Aeroespacial

    Sistemas de control de satélites y aviones usan memoria volátil para datos de vuelo en tiempo real con requerimientos estrictos de latencia.

    Medicina

    Equipos médicos como monitores de pacientes almacenan lecturas temporales en RAM para procesamiento en tiempo real antes de su persistencia.

    IoT Industrial

    Sensores y actuadores inteligentes en fábricas utilizan estos conceptos para gestión eficiente de datos en entornos de recursos limitados.

    Sistemas Criticos

    Centrales nucleares, sistemas de control ferroviario y plantas industriales aplican estos principios para garantizar operación confiable.

    Reflexion Final

    Los sistemas embebidos están en el corazón de la tecnología moderna. Comprender cómo gestionan su memoria, sincronizan su tiempo y exponen interfaces de control es fundamental para cualquier ingeniero de software o electrónico que trabaje en el ecosistema de hardware-software. KRAT OS proporciona un punto de entrada accesible e interactivo a este fascinante campo.
